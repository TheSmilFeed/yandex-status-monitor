# Что там по серверам Яндекса?

Учебный проект по дисциплине «Веб-аналитика»: доступность сервисов Московского Политеха и Яндекса, графики HTTP-проверок и журнал инцидентов. Автор — Литвинов Иван Александрович, группа 233-321.

Проект не является официальным сервисом Яндекса или Московского Политеха. Данные формируются на основе автоматических проверок и открытых источников. На текущем этапе подключены автоматические HTTP-проверки; внешние сигналы пока отсутствуют.

**Сайт:** https://thesmilfeed.github.io/yandex-status-monitor/

**Репозиторий:** https://github.com/TheSmilFeed/yandex-status-monitor

## Архитектура

Cloudflare Cron → Worker yandex-status-monitor → Supabase PostgreSQL → публичный API Worker → статический frontend на GitHub Pages.

Worker выполняет мониторинг по расписанию каждые пять минут. Frontend читает результаты GET-запросами и обновляет видимую страницу раз в минуту; посещение страницы не должно запускать мониторинг. Production Worker и база не изменены. Supabase и правила записи описаны владельцем; SQL, RLS и подлинный исходник Worker отдельно не аудировались. Свежесть и история проверены по публичному API 22.10.2026. Подробнее: [архитектура](docs/architecture.md).

## Публичный API

Базовый адрес: https://yandex-status-monitor.fbgh111.workers.dev

- /api/status — текущие проверки и инциденты восьми сервисов.
- /api/incidents — доступный журнал событий.
- /api/history?service=SLUG&limit=500 — последние проверки выбранного сервиса.

Запросы не содержат cookies, ключей Supabase или Authorization. Обрабатываются загрузка, сетевые ошибки, таймауты, неверный формат и пустые ответы. API возвращает Access-Control-Allow-Origin: *. Поля и ограничения описаны в [контракте API](docs/api-contract.md).

В каталоге девять карточек. Главная страница Яндекса пока отсутствует в API: карточка показывает «Нет данных», запрос истории для отсутствующего сервиса не отправляется после успешного чтения каталога API. Yandex Cloud не добавлен. ЦОДы Сасово, Владимир, Калуга, Мытищи и Ивантеевка показаны без вымышленных статусов и ping.

## Интерпретация данных

HTTP 200–399 подтверждает доступность адреса, но не всех функций сервиса. HTTP 401/403 означает неопределённость, возможна блокировка автоматической проверки. Результаты старше 15 минут не считаются актуальными. HTTP-ошибка Яндекса без внешнего подтверждения не объявляется массовым сбоем.

Для Политеха, по описанию backend, три последовательные неудачные проверки открывают инцидент; успешная проверка его закрывает. Frontend не создаёт и не закрывает события. В API отсутствует достаточная связь всех закрытых событий со slug: полный журнал показан на странице истории, а на странице сервиса — только однозначно связанные события.

График доступности показывает отдельные реальные HTTP-проверки. График времени ответа разрывает линию при пропусках более 12 минут. Фильтры 24 часа / 7 дней / 30 дней применяются к полученным 500 записям. Пустые участки не заполняются, полное покрытие периода и процент uptime не обещаются. Все даты — Europe/Moscow.

## Локальный запуск

Нужен Node.js 22 или новее, сторонних зависимостей нет.

~~~sh
node scripts/serve.mjs
~~~

Открыть http://127.0.0.1:4173/. Открытие HTML через file:// не поддерживается из-за модулей JavaScript.

~~~sh
node --test
node scripts/build.mjs
~~~

Сборка копирует frontend в dist/. Варианты npm run dev, npm test и npm run build доступны при установленном npm. Шрифт Manrope загружается из Google Fonts с системным Arial в качестве запасного. Значки сервисов условные, не официальные логотипы.

## GitHub Pages

Публикация уже включена. Источник в Settings → Pages — GitHub Actions. После отправки main workflow запускает тесты, собирает dist/ и публикует frontend. Рабочий адрес: https://thesmilfeed.github.io/yandex-status-monitor/.

Workflow не меняет backend и не использует секреты Cloudflare или Supabase. История изменений сохраняется в Git. Локальные .env, .dev.vars, ключи, сборка и проверочные артефакты исключены через .gitignore.

## Веб-аналитика

Актуальная последовательность: **ЛР3 — LiveInternet, ЛР4 — Sber Ads, ЛР5 — MyTracker**.

Все страницы подключают site.js, который использует общий analytics.js. Для видимого счётчика на каждой странице есть блок «Счётчики статистики» с контейнером analytics-counters. До получения официальных кодов счётчики отключены, идентификаторов и запросов в аналитические системы нет.

Подключение: использовать только выданный владельцу код; зарегистрировать соответствующий адаптер в analytics.js либо установить официальный сниппет по его требованиям. Если сниппет сам учитывает загрузку, не отправлять дополнительный просмотр из адаптера. AJAX-обновления статусов и переключения периода не считаются новой страницей. После установки проверить каждую HTML-страницу и отсутствие повторного учёта. [Инструкция по LiveInternet и ЛР3](docs/analytics.md).
