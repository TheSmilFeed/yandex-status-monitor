# Подготовка веб-аналитики

ЛР3 — LiveInternet, ЛР4 — Статистика от SberAds / Топ-100, ЛР5 — MyTracker, согласно плану проекта. Все три счётчика установлены 22.10.2026. Поступление первых данных LiveInternet подтверждено владельцем по отчёту. SberAds и MyTracker требуют проверки поступления данных после публикации.

| Статистика от SberAds / Топ-100 | 7753202 | Базовый учёт; заявка на участие в рейтинге на модерации (состояние кабинета 22.10.2026) |
| MyTracker | 3807709; приложение 1093228 | Web, проект «Что там по серверам Яндекса?», валюта RUB |

SberAds создан в кабинете владельца после подтверждения пользовательского соглашения. MyTracker создан в аккаунте «Веб-аналитика · Литвинов Иван». Его официальный код использует очередь _tmr и домен top-fwz1.mail.ru; надпись Top.Mail.Ru в коде соответствует выданному MyTracker сниппету.

Модули sberads.js и mytracker.js загружают официальные библиотеки асинхронно. Повторная инициализация в одном документе заблокирована. Дополнительные события, идентификаторы пользователей, ecommerce и рекламные кампании не настроены. Пиксели noscript не добавлены: сбор требует JavaScript и ограничен опубликованным адресом. Это также исключает отправку просмотров из локальных HTML-копий при выключенном JavaScript.

Кабинеты: [SberAds](https://ads.sber.ru/stat/projects), [MyTracker — веб-счётчик](https://app.tracker.my.com/app/webCounter/view/?idApp=1093228). В подвале установлены официальные картинки Рамблера и Mail.ru размером 88×31. Картинка Рамблера взята из шаблона виджета официальной библиотеки top100.js: counter-static/images/top100_0062b1.gif, ссылка ведёт на рейтинг с query=7753202. Mail.ru выдал отдельный код логотипа на странице top.mail.ru/code?id=3807709: тип 479, параметр l=1. Это логотип без второго вызова pageView; установленный код MyTracker сохранён. Изменение картинок не меняет права доступа к отчётам.

## Общее подключение

Каждая HTML-страница загружает frontend/js/site.js. Он подключает frontend/js/analytics.js и передаёт путь и заголовок страницы один раз. Обновление данных, выбор сервиса для графика и переключение периода не создают новых просмотров. Обычный переход по навигации открывает новый документ.

registerAnalytics принимает liveinternet, sberads и mytracker. Поздно зарегистрированный адаптер получает текущую страницу; повторная передача того же пути не дублируется. Ошибка адаптера не нарушает работу мониторинга. До регистрации адаптеров нет сетевых запросов в эти системы.

В #analytics-counters на всех восьми страницах размещена кнопка LiveInternet 88×31. Модуль liveinternet.js сохраняет параметры выданного кода: licntCDCA, t52.11, адрес страницы, заголовок, источник перехода и параметры экрана. Он назначает адрес картинки один раз через общий адаптер. Отдельного inline-скрипта или второго запроса нет. Счётчик запускается перед загрузкой мониторинга, поэтому недоступность API не мешает учёту посещения. Старые hash-ссылки учитываются только после перенаправления.

Запросы отправляются только с https://thesmilfeed.github.io/yandex-status-monitor/. Локальная разработка и копии сайта не отправляют просмотры. Автоматические тесты проверяют параметры без сетевых обращений. Блокировщики могут препятствовать загрузке счётчика.

## Действия владельца

1. Открыть опубликованный сайт и проверить кнопку в подвале.
2. Открыть статистику из ссылки счётчика, проверить поступление просмотров и соответствующие адреса страниц. Данные и цифры на кнопке обновляются не мгновенно. Если переходы не учитываются, проверить код, блокировщик и адрес зарегистрированного сайта.
3. Для входа использовать адрес сайта, указанный при регистрации, и пароль LiveInternet. Пароль не передавать другим.

Официальные материалы: [варианты счётчика](https://www.liveinternet.ru/code), [справка](https://www.liveinternet.ru/help/faq.html). LiveInternet допускает регистрацию каталогов сайта с завершающим слешом; отдельные HTML-страницы регистрировать не нужно.

## Начало сбора

Сначала установить код и убедиться, что реальные просмотры поступают. Затем отправлять друзьям и знакомым адрес https://thesmilfeed.github.io/yandex-status-monitor/ и предложить посмотреть интересующие сервисы, графики и историю. Не просить многократно перезагружать страницу. Учитывать реальных посетителей, а не число запросов Worker или просмотров одного человека.

По заданию нужны минимум 50 реальных пользователей и период сбора 1–2 недели. Скриншоты установки и первых данных можно сохранить сразу. Для итогового анализа дождаться достаточной выборки и согласованного периода. Числа посетителей за отдельные дни нельзя просто сложить для получения уникальных посетителей за весь период: один человек может возвращаться.

## После набора аудитории

Зафиксировать единый период анализа. Сохранить скриншоты посещаемости и доступных отчётов по источникам переходов, страницам, устройствам, браузерам и географии. Записать значения с датами и названиями метрик, затем описать наблюдения и ограничения. Сделать выводы и предложить улучшения сайта на основе фактических данных. Окончательный состав отчёта сверить с заданием ЛР3. Не подменять отсутствующие показатели и не копировать чужие материалы.
